# dsh-prompt-predict-adaptive

DeepSeek Harness 的输入框预测插件：一轮对话结束后，插件使用**该会话上次请求所选的模型和提供方**预测你可能输入的下一句话，并以灰字显示在输入框上方。

- 按 **Tab** 将建议填入输入框；不会自动发送，你可以继续编辑。
- 按 **Esc** 丢弃当前建议。清空输入框后，最近处理过的建议可能作为历史候选重新出现；再次按 Esc 可移除当前显示的历史候选。
- 可选的自适应功能会使用本会话中采纳或丢弃的示例，帮助后续建议贴近你的措辞；它不会训练模型权重。

> **费用与隐私**：插件通常会在每轮对话结束后额外发起一次模型请求，具体取决于触发、取消和会话状态，调用计入所选提供方的额度。按 Tab 或 Esc 不会撤销已经产生的费用。预测请求会把选定范围的对话文本发送给该会话所选的模型提供方；启用相关选项时，还可能包含工作区变更摘要、会话权限状态和采纳/丢弃示例。请按自己的隐私需求和费用预算决定是否启用。

## 兼容性

- 已在 Windows 上使用 DSH 桌面版内置的 **0.2.1-rc.5 Web 宿主**、本地模拟模型验证认证、设置持久化及 Tab/Esc。其他版本和真实模型提供方尚未在此次验证中覆盖。
- 桥接依赖宿主的 `connection.requestRejection`。如果接口不可用或认证检查出错，桥接会拒绝请求，不会退回仅凭请求头判断。
- 诊断端点默认关闭；启用后使用 `POST /prompt-predict-adaptive/diagnose?sessionId=...` 可发起真实预测调用。诊断开关不在当前设置界面中，属于开发用途。

## 安装与开始使用

本插件**没有发布到 npm**，可从 GitHub 或本地目录安装。

1. 在 Harness 中打开 **设置 → 插件 → 添加插件**，选择「Git 仓库」，输入：

   ```text
   https://github.com/NineStars-H/dsh-predict-adaptive
   ```

   也可以选择「本地目录」，填写本地克隆目录的绝对路径。

2. 安装后刷新页面，并在插件页确认「输入框预测（自适应）」已启用。
3. 在使用过模型的会话里完成一轮对话，等待预测显示。会话尚无上次请求的模型路由时，插件不会自行切换到默认模型。
4. 根据需要在插件设置中调整上下文、自适应及其他选项，点击**保存**。

生成建议有延迟，实际时间取决于模型、上下文和网络；并非每轮都一定出现建议。

## 设置

在 **设置 → 插件 → 输入框预测（自适应）** 中调整：

| 选项 | 默认 | 作用 |
|---|---|---|
| 输入框预测 | 开 | 控制是否生成建议 |
| 自适应 | 开 | 将本会话近期采纳和丢弃的示例加入后续预测提示 |
| 并入工作区状态 | 开 | 可用时加入宿主记录的本会话文件变更摘要，不主动扫描项目文件 |
| 继承会话权限 | 开 | 可用时将沙箱和审批状态加入预测提示 |
| 预测上下文 | 完整 | 使用可提取的全部对话文本，或切换为最近轮次 |
| 保留轮数 | 6 | 最近轮次模式下的用户轮数，范围 1–40 |

设置页的**重置**会清除学习示例。预测失败或额度不足时，可在插件设置页查看最近一次错误；插件不会为同一轮自动重试。

同一页还显示**预测消耗**：每轮对话结束后都会发起一次预测请求，而这次调用不会出现在对话记录里。这里列出本进程内累计的输入 / 输出 / 缓存 token 与调用次数，以及最近若干次的合计，便于估算单轮成本。**清零重新统计**可把计数归零，用于对比调整设置前后的开销。

供应商未报告用量时，该次调用会计入“未报告用量”，而不是被当成零成本。

## 数据、认证与卸载

预测是独立的模型请求，不作为主 Agent 步骤写入会话日志。请求内容仍会发送给所选模型提供方，并受该提供方的数据处理和计费方式约束。

插件将设置和学习示例保存到 `prompt-predict-adaptive` 目录：

| 文件 | 内容 |
|---|---|
| `config.json` | 插件设置 |
| `feedback.json` | 每个会话近期采纳和丢弃的示例，最多保留 20 个会话 |

目录根路径依次使用 `DSH_PROFILE_DIR`、`DSH_HOME`；两者都未设置时使用宿主进程的当前工作目录。示例可能包含对话相关内容，请像处理会话数据一样保护它们。

停用、重载、重启和卸载不会由插件自动删除这些数据。宿主清理回调不能可靠地区分停用与卸载；如果不再需要数据，请在卸载后**先确认实际根路径**，再手动删除其中的 `prompt-predict-adaptive` 目录。设置页的重置只清除学习示例，不删除配置。

**卸载后清理残留数据。** 这是本插件唯一留在包体之外的东西。以本机默认布局为例，目录是 `%USERPROFILE%\.dsh\profiles\desktop\prompt-predict-adaptive`，其中 `feedback.json` 通常只有几百字节：

```powershell
# 确认路径无误后再删除
Get-ChildItem "$env:DSH_PROFILE_DIR\prompt-predict-adaptive"
Remove-Item "$env:DSH_PROFILE_DIR\prompt-predict-adaptive" -Recurse -Force
```

`node_modules` 下的插件目录、profile 的 `package.json` 与 `pnpm-lock.yaml` 中的条目会随卸载一并移除；上面的状态目录不会，需要手动删。

桥接复用 DSH 的会话认证和 Host/Origin 检查，修改请求还要求 `Origin`。这不改变所选模型提供方对预测请求的处理方式。

## 已知限制

- **延迟不是零。** 生成一次建议通常要 4–10 秒，长会话更久；这段时间输入框是空的，不要以为是坏了。
- **只读对话，不读项目文件。** 工作区状态借用宿主已有的变更摘要（改过哪些文件、增删多少行），不主动扫描文件系统。
- **失败不重试。** 限流或额度耗尽时跳过这一轮，并在插件设置页显示原因；等下一轮自动恢复。
- **Web UI 插件需要刷新页面**才会加载或消失。
- **每轮多一次调用。** 见开头的费用提示，这里不再重复。

### 已修复：长会话重复计费

1.0.1 及更早版本在**工具密集的长会话**里可能对同一轮对话发起两次模型请求。原因是去重键用了 `turn/end` 的序列号：`agent/turn-stopping` 触发时该事件尚未写入，键指向上一轮；等它写入后键又变了，2 秒轮询就把同一轮当成新的一轮再扣一次费。短会话因为 `user/message` 的序列号还能当兜底键而幸免，一旦工具事件把它挤出 400 事件扫描窗口就会复现——恰好是最费额度的那类会话。

现在改为用**轮次编号**去重，它在回合开始前就已确定，不会因事件写入而改变。长窗口和无用户消息的回合都有回归测试覆盖。**如果你在 1.0.2 之前安装过并长时间使用工具密集的会话，历史账单可能包含这类重复调用。**

### 已修复：发送后建议重新出现

1.0.2 及更早版本里，一轮对话结束会先生成一条建议；如果你没有采纳而是自己发了消息，下一次轮询会把「刚结束的那轮」和「你的新消息」一起看到，于是又为**你已经翻过去的那一轮**生成一次建议。结果就是输入框刚清空，灰字立刻又冒出来，并一直留到你再次发言，同时还多花了一次模型调用。

现在只要发言晚于该轮结束，就不再为它预测；而**先于**该轮结束到达的发言属于正常回复，仍然照常预测。两个方向都有回归测试覆盖。

### 已修复：Esc 不生效，以及 Tab 发送后灰字滞留

1.0.3 及更早版本有两个独立的界面问题。

**Esc 按了没用。** 界面显示的是「当前建议，没有则回退到最近的历史建议」。旧版在按下 Esc 后把被丢弃的那句写回了历史环，于是下一次轮询（2.5 秒）又从历史里把它画了出来——看起来就像 Esc 只生效了两秒半。现在丢弃就是移出历史环，两个分支都不再回写。

**Tab 填入并发送后，灰字要滞留几秒。** 旧版靠「输入框阶段变成 `submitting`」来判断「刚发送了」，但宿主只在命令或 chip 提交通道上进入 `submitting`，**普通发送全程是 `plain`**，所以这个判断从未触发过。现在改为观察输入框由非空变空——这是每次发送都会发生的事——立即清掉本地副本；随后由宿主决定是否恢复。

这里刻意**不在客户端自行标记「已消费」**：宿主才是历史环的权威。客户端只报告「输入框空了」，由宿主按会话日志判定这是发送还是清空——发送会新增 `user/message`，清空不会。因此「清空输入框后建议自动回来」这个行为得以保留。

## 故障排查

**没有显示建议**

1. 确认插件和「输入框预测」开关已启用，安装或切换后已刷新页面。
2. 确认会话已有上次请求的模型路由，并等待一轮对话完成。
3. 查看插件设置页的最近错误；限流、额度不足或提供方失败可能导致本轮没有建议。
4. 如果设置页无法连接并显示 HTTP 503，请检查当前 DSH 宿主是否提供兼容的 `connection.requestRejection` 接口。

**Windows 上从本地目录切换到 Git 安装时出现 `ERR_PNPM_EPERM`**

旧安装可能在 profile 的 `node_modules` 中留下指向本地目录的 junction。先在插件页卸载，再检查实际 profile 下的 `dsh-prompt-predict-adaptive` 项是否仍是指向旧目录的链接；确认后仅移除该链接，再尝试安装。不要递归删除链接目标或不确定的目录。

## 工作原理

插件监听会话结束、Agent 状态及停止事件，并以会话日志轮询作为兜底。事件是主路径；轮询只用来兜住「会话在 `agent/created` 之前就存在」和「某个 `turn/end` 事件被漏掉」两种情况，因此间隔为 5 秒——它几乎总是空转，不必跑得更勤。

插件把可提取的用户和助手消息整理成纯文本转录，**以一句悬空的 `USER:` 结尾**，再附上预测指令。这个悬空收尾是关键：没有它，输入读起来是「一份已完成的文档加一个任务」，模型就会写出助手口吻的下一步计划；有了它，任务变成「补完这句话」。转录不包含工具结果、工具定义或会话系统提示。

预测调用直接使用 `ctx.llm.stream()`，不产生主会话的 Agent 步骤。会话未记录提供方或模型时，插件返回空结果，不回退到其他路由。

建议显示在输入框内、官方占位符所在的同一矩形区域，最多两行，超出以省略号结尾（Tab 仍会填入全文）。这个高度上限来自布局约束：浮层的锚点是 `height: 0` 的绝对定位元素，不参与布局，第三行会盖住下方工具栏而不是把卡片撑高。

Esc、发送与清空都由本地状态或会话日志判定，不等轮询：Esc 在按键当帧恢复官方占位符，发送当帧消失，清空后立即召回。

## 数据、认证与卸载

插件只写自己状态目录下的文件，不修改 DSH 本身：

- `config.json`：设置
- `feedback.json`：已采纳 / 已丢弃的草稿，用于自适应
- `suggestions.json`：每次预测的记录（文本、轮次、结果、token、上下文摘要），最多 120 条

后两者是诊断与学习用的；删掉它们不会影响插件运行，只会丢掉已学内容与历史。
