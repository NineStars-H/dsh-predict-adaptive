# 输入框预测（dsh-prompt-predict-adaptive）

给 [DeepSeek Harness](https://github.com/deepseek-ai) 用的输入框预测插件。

一轮对话结束后，插件会用**这个会话上次请求所选的模型**猜测你接下来想说什么，把结果以灰字显示在输入框里。按下 Tab 填入，接着改或直接发都行。

```
┌──────────────────────────────────────────┐
│ 跑一下测试，把失败的几条贴出来               │  ← 灰字建议
│                                          │
│  +   完全权限    DeepSeek-V4.1-Flash  ↑  │
└──────────────────────────────────────────┘
```

## 功能

- **Tab 填入** —— 建议变成可编辑的草稿，不会自动发送
- **Esc 丢弃** —— 立即消失，不会再冒出来
- **清空召回** —— 清空输入框后，刚处理过的建议会回来；发过消息则不会
- **自适应**（可选）—— 从你采纳或丢弃的建议里学习措辞，只影响本会话的提示，不训练模型
- **消耗可见** —— 设置页显示预测累计花掉多少 token，以及最近每次的用量

## 安装

插件没有发布到 npm，从 GitHub 或本地目录安装。

1. 打开 **设置 → 插件 → 添加插件**
2. 选择「Git 仓库」，填入：

   ```text
   https://github.com/NineStars-H/dsh-predict-adaptive
   ```

   也可以选「本地目录」并填写克隆下来的绝对路径。

3. 安装完成后**刷新页面**
4. 在插件页确认「输入框预测」已启用

Web UI 插件都需要刷新页面才会加载。

## 开始使用

1. 在一个用过的会话里正常聊一轮
2. 等回复结束，输入框出现灰字
3. 按 **Tab** 填入，或按 **Esc** 忽略

第一轮不会立刻有建议——插件需要知道这个会话用的是哪个模型。如果会话还没有模型路由，插件不会替你选一个。

## 设置

**设置 → 插件 → 输入框预测**

| 选项 | 默认 | 说明 |
|---|---|---|
| 输入框预测 | 开 | 总开关 |
| 自适应 | 开 | 把本会话采纳/丢弃过的建议作为措辞参考 |
| 并入工作区状态 | 开 | 加入本会话改过哪些文件，让建议能点名具体文件 |
| 预测上下文 | 完整 | 用整段对话，或只取最近几轮 |
| 保留轮数 | 6 | 「最近轮次」模式下的用户轮数，1–40 |

**预测消耗** 一栏显示：

- 每轮大约多少 token
- 累计调用次数与总量
- 「清零」把计数归零，方便对比调整设置前后的开销

展开「查看每次预测」可以看到每次建议的原文、时间、结果（已采纳 / 已丢弃 / 已覆盖）和当轮消耗。

## 费用

**每轮对话结束后会额外发起一次模型请求**，计入你所用提供方的额度。按 Tab 或 Esc 不会撤销已经产生的费用。

预测请求会把选定范围内的对话文本发送给该会话所用的模型提供方。开启相应选项时，还可能包含工作区变更摘要，以及采纳/丢弃的示例。

预测请求本身是只读的：它不携带工具、不执行任何操作，返回的文本只会显示在输入框里。

用「最近轮次」而不是「完整」可以明显降低单次消耗——完整模式会重放整段对话，会话越长越贵。

## 数据存放

插件只在 profile 下写自己的状态目录，不修改 DSH 本身：

| 文件 | 内容 |
|---|---|
| `config.json` | 设置 |
| `feedback.json` | 各会话采纳 / 丢弃过的建议，最多 20 个会话 |
| `suggestions.json` | 每次预测的记录，最多 120 条 |

目录位置依次取 `DSH_PROFILE_DIR`、`DSH_HOME`；都没设置时用宿主进程的当前工作目录。

这些文件可能包含对话内容，请像对待会话数据一样保管。

### 卸载

在插件页卸载即可移除插件本身。**状态目录不会自动删除**——如果不再需要，手动删掉：

```powershell
# 先确认路径，再删除
Get-ChildItem "$env:DSH_PROFILE_DIR\prompt-predict-adaptive"
Remove-Item "$env:DSH_PROFILE_DIR\prompt-predict-adaptive" -Recurse -Force
```

`node_modules` 里的插件目录、profile 的 `package.json` 和 `pnpm-lock.yaml` 条目会随卸载一并清理。

## 常见问题

**没有出现建议**

1. 确认插件已启用，并且装完刷新过页面
2. 确认这个会话已经有过一轮完整的对话
3. 看设置页的最近错误——限流、额度不足都会导致本轮跳过
4. 长会话里生成会慢一些，通常几秒，可以再等等

**建议内容不准确**

灰字是模型的猜测，不是事实陈述。它可能猜错，也可能在没把握时干脆不出现。按 Esc 忽略即可。

如果反复出现同一类偏差，可以在设置页展开「查看每次预测」，那里记录了每条建议生成时的对话上下文。

**Windows 上从本地目录换成 Git 安装时报 `ERR_PNPM_EPERM`**

旧安装可能在 `node_modules` 里留下指向本地目录的 junction。先在插件页卸载，确认那个条目仍是指向旧路径的链接后，只移除链接本身，不要递归删除目标目录。

**设置页显示 HTTP 503**

桥接依赖宿主的 `connection.requestRejection` 接口。如果当前 DSH 版本不提供，插件会拒绝请求而不是放行——这是有意的。

## 兼容性

- 需要 DSH 桌面版内置的 Web 宿主，桥接依赖 `connection.requestRejection`
- 预测使用会话上次请求的模型，不会回退到其他路由
- 不扫描项目文件；工作区信息来自宿主已有的变更摘要
